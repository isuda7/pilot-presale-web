# 4. 업데이트 (버전별 진행 내역)

> 파일럿이 어떤 순서로 만들어졌는지 버전별로 정리한 기록이다. 각 버전의 첫 항목은 버전의 목표이고, 그 아래는 실제로 구현·정리한 내용이다.
> 새 기능을 추가할 때마다 이 문서와 저장소 루트의 `CHANGELOG.md`를 함께 갱신한다. 현재 버전은 **v0.4**다.

| 버전 | 한 줄 요약 |
|---|---|
| **v0.1** | 파일럿 개발 기본환경 구축, 분양 신청 받기·신청 확인 |
| **v0.2** | 파일럿 기획·설계 환경 구축, 매뉴얼·템플릿 유형 추가 |
| **v0.3** | 분양 데이터 관리자모드 **백엔드** 편집 기능 추가 |

## v0.1

* **파일럿 개발 기본환경 구축**
* **분양 신청 받기, 신청 확인**

### 구현 내용
- **개발 환경**: 프론트 HTML/CSS/JS(Vite 멀티페이지), 백엔드 Hono(Vercel Function), DB Turso(libSQL, 로컬은 `local.db` 파일). 로컬 실행은 `npm run dev`(웹 5180, API 8790).
- **배포 환경**: GitHub 저장소 → Vercel 자동 빌드·배포. 환경변수 4개(`ADMIN_PASSWORD`, `TOKEN_SECRET`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`).
- **분양 신청 받기**: 신청 화면(성함·연락처·문의사항·개인정보 동의), 서버 검증(필수값·연락처 형식·동의), DB 저장.
- **신청 확인**: 관리자 로그인(비밀번호 1개, 서명 토큰 12시간), 신청 목록(최신순), 상태 변경(신규/연락완료/처리완료), 삭제(소프트 삭제).
- **기본 화면**: 메인, 사업안내·단지안내·세대안내(빈 콘텐츠 영역), 방문예약(신청), 관리자.
- **배포하며 정리한 것**: 서버 코드 상대 import에 `.js` 확장자 필수(서버리스 크래시), `.gitignore` 정비, 환경변수 변경은 재배포 후 적용 → 이 판단들은 가이드 1장에 기록했다.

## v0.2

* **파일럿 기획·설계 환경 구축**
* **매뉴얼, 템플릿 유형 추가**

### 구현 내용
- **기획·설계 문서**: 전체 기획(`docs/01`), 단계별 처리 범위 S0~S7(`02`), 원본·감시 프롬프트(`03`, `CLAUDE.md`에 등록), 현장 수정 범위·설정 구조(`04`), 전파·운영·종료(`05`).
- **분류 체계**: L1 필수 공통 / L2 선택 공통 / L3 예외 유형 / L4 현장 고유 데이터. 후보 사이트 10곳의 메뉴를 매트릭스로 비교해 레벨을 판정(`docs/benchmark.md`).
- **구조**: 기본 → 유형 → 현장 순으로 덮어쓰는 설정(`config/base.ts`, `types/<유형>/type.ts`, `config/site.ts`), L2 켜고 끄기, 신청 폼 정의 공유(화면·서버 검증).
- **매뉴얼**: 가이드 3개 장(세팅·판단 노하우 / 디자인 시스템 규칙 / 후보→레벨 설계 활용)과 가이드 화면(`/guide/`, 기본 빌드에서만 포함).
- **템플릿 유형 추가**: 표준 디자인 시스템 1개 위에 **최소형 · 풀옵션형 · 중간형 A(분양정보형) · 중간형 B(비주얼형)** 4종. 레이아웃 변형(헤더·히어로·서브 이동), 메뉴 구성, 메인 섹션 구성, 콘텐츠가 유형마다 다르다.
- **이미지**: 유형별 사진 세트(Pexels 무료 사진 20장, 출처 `CREDITS.md`)와 CG 이미지(지도·평면도·기본).
- **데모 미리보기**: 개발 서버 한 곳에서 `/t/`로 4종을 이동하며 확인, 배포용은 `npm run build:demo`.
- **운영 보조**: 관리자 검색·기간·상태 조회와 CSV 다운로드, 신청 마감 스위치(`formClosed`), 오픈 전 점검 도구(`npm run check:site`), 버전·전파·종료 절차, 변경 이력(`CHANGELOG.md`).

## v0.3

* **분양 데이터 관리자모드 백엔드 편집 기능 추가**

### 구현 내용
- **DB 저장**: 수정한 콘텐츠를 `site_content` 테이블에, 수정 전 값을 `site_content_history`(항목별 최근 20개)에 저장. 서버가 첫 요청에 테이블을 자동 생성.
- **적용 순서 확장**: 기본 → 유형 → 현장 파일 → **DB 수정값(마지막)**. DB에 값이 없으면 파일 기본값으로 동작하고, API가 없어도 3초 후 파일 기본값으로 동작.
- **유형별 분리(scope)**: 유형 이름별로 따로 저장하므로 DB 하나를 템플릿 4종이 써도 섞이지 않는다.
- **API**: `GET /api/content`(공개), `PUT|DELETE /api/admin/content`, `GET /api/admin/content`, `GET /api/admin/content/history`.
- **스키마·검증**(`config/content-schema.ts`): 항목별 형식·길이·개수를 서버가 저장 전에 검사. 개인정보 문구·보유기간·고지문·메뉴 구조는 저장을 거부(사람 확정 항목).
- **관리자 콘텐츠 편집 탭**: 항목 목록 + 블록 종류(이미지·문단·표·카드·목록)로 자동 구성되는 폼, 초기값으로 되돌리기, 이력 보기·복원. 모든 템플릿이 같은 화면을 쓴다.
- **개발자용 동기화**: `npm run content -- export|import`(파일 ↔ DB, 검증 후 반영, 덮어쓴 값은 이력 보관, `--replace`는 `--yes` 필요).
- **보안 보강**: DB에서 오는 값을 화면에 그리는 모든 곳을 이스케이프(HTML 실행 방지). 감시 규칙 B10(DB 콘텐츠 변경 전 백업).

## v0.4

* **분양 데이터 관리자모드 프론트엔드 편집 기능 추가**

### 구현 내용
- **인라인 편집 모드**: 사용자 화면 위에서 바로 문구를 눌러 고치고 저장. 관리자 화면의 **사이트에서 직접 편집 ↗** 또는 로그인 후 주소 끝 `?edit=1`로 진입. 방문자에게는 편집 코드가 로드되지 않는다.
- **편집 가능한 것**: 현장명·전화·주소·운영시간, 메인 제목·설명·소제목·보조 버튼, 요약 수치, 소개 문단, 표 셀, 카드 제목·설명, 목록 항목. 같은 값이 여러 곳에 있으면 함께 바뀐다.
- **행·카드 추가(＋)와 삭제(✕)**: 표, 카드, 목록, 요약 수치, 분양일정 타임라인. **이미지 변경**: 그 유형의 이미지 세트에서 선택.
- **편집 바**: 편집 모드 켜기/끄기, 수정 건수, 저장, 변경 취소, 저장 전 이탈 경고.
- **저장**: v0.3의 같은 API·검증·이력을 사용. 기본 정보는 바꾼 필드만 저장하고, 본문은 해당 항목 전체를 저장.
- **잠금(🔒)**: 개인정보 문구, 고지문, 메뉴 이름·구조, 신청 버튼 문구, 레이아웃은 편집 표시가 붙지 않아 수정할 수 없다.
- **구현 규칙**: 화면 조각의 데이터 위치는 `data-e` · `data-f` · `data-block` · `data-row` 표시로 안다. 새 컴포넌트는 이 표시를 붙여야 편집된다.

## 현재 한계 · 다음 후보
- **배포 환경 검증 미실시**: Vercel(서버가 `config/`·`types/`를 읽는 구조, 새 테이블 자동 생성, 데모 프로젝트)에서의 동작은 아직 확인하지 못했다. 배포 후 신청 → 관리자 확인 → 콘텐츠 수정까지 한 번 확인해야 한다.

- **미지원**: 이미지 업로드, 글자 서식, 개별 계정·수정자 기록(비밀번호 1개), 동시 편집 충돌 방지(나중 저장이 이김), 변경 전후 비교.
- **다음 버전 후보**: 풀옵션형 전용 컴포넌트(평면 탭·갤러리·FAQ), 이미지 업로드, 권한 분리(신청 확인 / 콘텐츠 수정), 신규 신청 알림.
