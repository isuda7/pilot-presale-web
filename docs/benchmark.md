# benchmark. 후보 10개 분석 (S1)

> 기준: `01-master-plan.md` §4 레벨 체계. 이 문서의 결론은 **제안**이며, 확정은 사용자 확인 후.
> 확인일: 2026-11-10. 방법: 각 사이트 **메인 페이지의 내비게이션·섹션**을 읽음. 하위 페이지 본문은 열어보지 않았다.

## 0. 한계 (먼저 읽기)
- 후보 10곳이 모두 **푸르지오·써밋 계열**이다. 둘 다 같은 건설사 브랜드로 알려져 있으나 사이트 푸터로 확인하지는 않았다. "분양 사이트 전체의 평균"이 아니다.
- 메뉴는 메인 페이지에서 읽은 것이다. 메뉴에 없다고 해서 사이트에 해당 페이지가 없다는 뜻은 아니다(특히 9번은 하위 메뉴가 안 보임).
- **신청 폼 입력 항목은 10곳 모두 미확인**이다(별도 페이지/외부 사이트로 연결). 8번의 개인정보 안내에 수집 항목 "성명, 전화번호, 주소"가 있으나 실제 폼 항목인지 미확인.
- 읽기 방식의 한계로 일부 항목을 놓쳤을 수 있다. 판정 경계(3~5곳)의 항목은 직접 열어 확인이 필요하다.

## 3. 판정에서 나온 설계 관찰
1. **L1은 작다**: 사업개요, 입지환경, 프리미엄, 오시는길, 홍보센터(언론보도), 신청 폼 + (전 사이트 본문에 있는) 푸터 고지·개인정보처리방침·전화·지도 링크·팝업.
2. **계약 안내 문서(인지세·자금조달·명의변경·예비입주자…)는 메뉴가 아니라 한 페이지 안의 목록**이다. 사이트마다 개수·이름이 다르므로 **L4(목록 값)**로 두고, 계약안내 페이지 하나를 L2로 켜고 끄는 방식이 맞다.
3. **마감재 리스트**도 같은 이유로 세대안내 페이지 내부 항목이다.
4. **써밋 2·5번은 별도 구조가 아니라 표준형 + 계약안내 확장 + 방문예약**이다. 이전 가설에서 2·5번을 묶은 "조합·토지등소유자형"은 맞지 않다(토지등소유자 계약안내는 5번만, 2번은 해당 없음). 표준형의 L2를 켜는 설정 차이로 흡수 가능.
5. **간결형(9, 10)**은 평면 메뉴이고 단지·세대 안내가 본문 섹션으로 들어가 있다. 표준형의 L2를 끄는 설정만으로는 안 되고, **"메뉴 없이 한 페이지에 이어 붙이는 레이아웃"**이라는 구조 차이가 있다 → 별도 구조 유형.
6. **8번(청라 아크원)**은 청약안내 + 아파트/오피스텔 분리로 메뉴 트리 자체가 다르다 → 별도 구조 유형. 단, 청약안내는 10번에도 있어 L2 승격 대상.

## 4. 유형(템플릿) 묶음 제안
> **2026-11-10 변경(사용자 결정)**: 아래 A/B/C 묶음 제안은 후보 분석 결과이며, 실제 데모 템플릿은 **최소형 · 풀옵션형 · 중간형 A(분양정보형) · 중간형 B(비주얼형)** 4종으로 구성했다. 디자인 시스템은 표준 1개이고 `docs/04-site-edit-guide.md`에 정리했다. 후보 분석의 L1/L2/L3 판정은 그대로 메뉴 구성의 근거로 쓴다.

| 구조 유형 | 해당 | 핵심 | 레벨 구성 |
|---|---|---|---|
| **A. 표준형** (기본) | 1, 3, 4, 6, 7 (+2, 5) | 사업·분양·계약·단지·세대·홍보센터 | L1 + L2 켜기. 2·5는 계약안내·방문예약을 켠 설정 |
| **B. 간결형** | 9, 10 | 평면 메뉴 + 본문 스크롤, 청약안내(10) | L1 + L2 일부 + 평면 레이아웃(L3) |
| **C. 복합·청약형** | 8 | 청약안내 중심, 아파트/오피스텔 분리 | L1 + 청약안내(L2) + 용도 분리 메뉴(L3) |

- 구조 3종 × 디자인 2종 = 최대 6조합. 상한(구조 2~3 × 디자인 2) 범위 안. 템플릿은 **구조 3개 + 디자인 변형 1개 = 4개** 또는 구조 3개로 시작하는 안을 제안한다.
- **토지등소유자 계약안내(5번)**는 1곳뿐이라 L3 모듈로 두고, 같은 요구가 한 번 더 나오면 L2로 올린다.
- 디자인 시스템 2종의 기준은 후보 분석으로 정하지 못한다(색상·타이포는 이번에 비교하지 않음). 기존 디자인 시스템 유무 확인이 필요(§11-6).
