# 02. 구현 단계별 처리 범위

> 기준: `01-master-plan.md`. 각 단계는 **앞 단계가 끝나야 시작**하고, 범위 밖 항목은 하지 않는다.
> 검증 원칙: 구조 관련 단계(S2~S4)는 **서로 다른 현장 2개**로 검증한다. 1개로만 만들면 공통과 현장 고유를 구분할 수 없다.

## 전체 로드맵

| 단계 | 이름 | 한 줄 요약 |
|---|---|---|
| S0 | 기획 정리 | 전체 기획·범위·프롬프트 문서화 (이번 작업) |
| S1 | 후보 분석 | 10개 후보 매트릭스 → L1~L4 판정 → 유형 묶음 확정 |
| S2 | 내부용 초안 보강 | 판정 결과를 기본에 반영 (L1·L2 구현, 하드코딩 제거) |
| S3 | 덮어쓰기 구조 | 유형 정의 형식과 병합 규칙 구현 |
| S4 | 비즈니스 템플릿 | 유형별 템플릿 3~4개 (가상 데이터) |
| S5 | 가이드 매뉴얼 | `docs/guide/` 3개 장 → 이후 `/guide` 화면 |
| S6 | 복제 검증 · 관리 보강 | 실제 복제 1회 + 관리자 검색·CSV |
| S7 | 전파·운영 | 버전 태그, 전파 절차, 4개 운영, 종료·파기 1회 |

---

## S0. 기획 정리 (이번)
- **포함**: `01-master-plan.md`, `02-implementation-scope.md`, `03-prompts.md`
- **제외**: 코드 변경
- **완료 기준**: 3개 문서 검토 완료, 남은 확인 사항에 대한 답 수령

## S1. 후보 분석
- **포함**
  - `docs/benchmark.md`: 사이트 목록표, **메뉴 비교 매트릭스**(항목 × 10곳, 보유 곳 수), 신청 폼 비교, 사이트별 메모
  - L1~L4 판정(전부=L1, 절반 이상=L2, 소수=L3, 값만 다름=L4)
  - 유형 묶음 확정(표준 / 간결 / 오피스텔 병행 / 조합형 가설 검증, 간결형 흡수 여부)
  - 미확인 항목(폼 입력 항목) 목록과 직접 열어 확인할 대상
- **제외**: 다른 브랜드 확보(주소 제공 시에만), 코드
- **산출물**: `docs/benchmark.md`
- **완료 기준**: 모든 메뉴 항목에 레벨이 붙고, 템플릿 3~4개 구성이 확정됨

## S2. 내부용 초안 보강
> 진행 상태(2026-11-10): 구현·로컬 검증 완료, **배포 환경 검증 미실시**(Vercel에서 `config/form.ts` 공유가 동작하는지). 결과 문서는 `04-site-edit-guide.md`.
- **포함**
  - 하드코딩을 설정으로 이동: 푸터 고지, 개인정보 동의문, 사이트명, 전화, `<title>`
  - **L1 확정 구현**, **모든 L2를 구현**하고 켜고 끄기 설정으로 제어
  - 디자인 토큰 분리(`:root` 변수 범위 확정)
  - 신청 폼 항목 정의를 **한 곳**에 모아 화면·서버 검증이 어긋나지 않게 함
  - 내부용 초안의 접근 제한·`noindex`
  - 수정 허용/금지 파일 경계 문서화
- **제외**: 유형 병합 로직(S3), 템플릿 제작(S4), CSV·검색(S6)
- **완료 기준**: 설정만 고쳐 현장명·전화·메뉴·고지문이 바뀌고, L2 항목을 켜고 끌 수 있음. 로컬 + 배포에서 신청→관리자 확인 통과

## S3. 덮어쓰기 구조
> 진행 상태(2026-11-10): 구현·로컬 검증 완료(기본·유형별 빌드, 개발 서버 2종, 서버 폼 해석). **Vercel 배포 검증 미실시**. 설명은 `04-site-edit-guide.md`의 "유형 선택과 덮어쓰기".
- **포함**
  - 유형 정의 형식(이름, 디자인 토큰, L2 켜기/끄기, L3 모듈, 메뉴 구성, 폼 항목)
  - 병합 규칙: 기본 → 유형 → 현장 데이터
  - 파일 교체 규칙(유형 폴더에 같은 경로가 있으면 우선) + 교체 목록 기록 방식
  - 유형 선택으로 빌드되는 방법(환경변수 또는 설정 값)
- **제외**: 자동 생성기(스캐폴드 명령), 관리자 편집, 멀티테넌트
- **완료 기준**: 유형 폴더에 **다른 값만** 두고 빌드했을 때 해당 유형으로 나오고, 유형이 없으면 기본이 그대로 나옴. 서로 다른 유형 2개로 확인

## S4. 비즈니스 템플릿 3~4개
> 진행 상태(2026-11-10): 템플릿 4종 구현·로컬 검증 완료. **스킨·테마는 폐기하고 표준 디자인 1개로 통일, 템플릿을 최소형·풀옵션형·중간형 A·B 4종(레이아웃 변형·메뉴·메인 섹션·콘텐츠 차등)으로 재구성(사용자 요청, 2026-11-10). 이미지(사진·CG)는 유형별로 유지**(빌드 5종, 화면, 샘플 신청이 저장되지 않음). **기획자 검수와 공개 주소 열람은 미실시**. 샘플 신청 폼 처리: 사용자 결정(2026-11-10)으로 **실제 현장과 동일하게 저장·관리자 목록 사용**(출처 컬럼으로 구분). 설명은 `04-site-edit-guide.md`.
- **포함**
  - S1에서 확정한 유형별 템플릿(디자인 시스템 포함, 구조×디자인 상한 준수)
  - **가상 데이터만** 사용(가상 현장명·번호·저작권 문제없는 이미지)
  - 외부 공개용 안전장치: 샘플 신청 폼 처리, 샘플 고지, 관리자 접근·검색 노출 정책
- **제외**: 실제 현장 정보, 외부 노출용 관리자 화면
- **완료 기준**: 템플릿 각각이 공개 주소에서 열리고, 실제 개인정보가 저장되지 않음. 기획자 검수 통과

## S5. 가이드 매뉴얼
> 진행 상태(2026-11-10): `docs/guide/` 3개 장 작성, `/guide/` 화면 구현(`guide/` 폴더)(유형 지정 빌드에서 자동 제외). **"처음 보는 사람이 문서만 보고 복제·배포"는 S6에서 검증 필요**. 1장의 "프롬프트 과정" 형식(기록 vs 예시 모음)은 사람 결정 대기.
- **포함**
  - `docs/guide/01-setup.md`: 초기 세팅·가입 절차·판단 노하우·프롬프트 과정 (이 세션의 판단 사례 표 포함)
  - `docs/guide/02-design-system.md`: 공통 범위·덮어쓰기 규칙
  - `docs/guide/03-benchmark-levels.md`: 후보 → 4레벨 → 설계 활용
  - 이후 `/guide` 화면화(비공개·`noindex`·접근 제한, **현장 복제 시 제외 절차**)
- **제외**: 외부 공개
- **완료 기준**: 처음 보는 사람이 문서만 보고 현장 1개를 복제·배포할 수 있음 (S6에서 검증)

## S6. 복제 검증 · 관리 보강
> 진행 상태(2026-11-10): 관리자 검색·상태·기간 조회와 CSV 다운로드 구현·검증 완료. **로컬 복제 시험 완료**(막힌 곳은 가이드 1장 6절에 반영). **새 GitHub 저장소·Turso DB·Vercel 프로젝트로 실제 복제하는 부분은 미실시**(사람의 계정 작업 필요). 알림은 요구 확인 후.
- **포함**
  - 템플릿에서 **실제 복제본 1개**를 체크리스트(13단계)대로 생성: 새 저장소, Turso DB, Vercel 프로젝트, 환경변수
  - 누락·모호한 단계를 매뉴얼에 반영
  - 관리자: 검색/기간 조회, CSV 다운로드 (알림은 요구가 확인되면)
- **제외**: 개별 계정·로그인 기록, CRM 연동
- **완료 기준**: 신청→관리자 확인→CSV 추출 통과, 매뉴얼 보완 완료

## S7. 전파 · 운영
> 진행 상태(2026-11-10): 문서(`05-operations.md`), `CHANGELOG.md`, `docs/sites.md`, 점검 도구(`npm run check:site`), 신청 마감 스위치 구현. 전파·충돌 처리는 임시 저장소(템플릿 1 + 현장 1)에서 시험. **실제 현장 2곳 전파 검증, 4개 현장 운영, 종료·파기 1회 수행은 미실시**(실제 저장소와 사람의 결정 필요).
- **포함**: 템플릿 버전 태그, upstream 병합 절차 문서화, 현장×버전 표, 공통 수정 1건을 복제본 2곳에 전파 검증, 4개 현장 운영, 종료·파기 절차 1회 수행
- **제외**: 자동 전파 도구
- **완료 기준**: 현장 1곳이 오픈부터 종료·파기까지 완료

## 이번 단계 전체의 범위 밖 (하지 않는 것)
- 멀티테넌트(`site_id`), 한 코드베이스에서 현장을 자동 생성하는 구조
- 외부 CMS 연동, 이미지 업로드, 항목별 수정자 기록·개별 계정
  - (관리자 화면의 **콘텐츠 웹 편집**은 2026-11-10 사용자 요청으로 구현함 — `04-site-edit-guide.md`)
- 도메인 연결 자동화
- 현장별 개별 계정·로그인 기록·권한 체계
- 신청 데이터 대행사 CRM 연동

## 의존 관계
```
S0 → S1 → S2 → S3 → S4 ──┐
            └→ S5 ←──────┘ (S5는 S2부터 병행 작성, S6에서 검증)
                    S4,S5 → S6 → S7
```

## 단계 진입 전 확인 (게이트)
| 게이트 | 필요한 답 |
|---|---|
| S1 진입 | 후보 보강 여부(다른 브랜드 주소) |
| S2 진입 | 신청 폼 항목이 현장마다 다른가 |
| S3 진입 | 디자인 시스템이 이미 있는가, 유형 정의를 둘 방식 |
| S4 진입 | 외부 공개 샘플 신청 폼 처리 방식 |
| S6 진입 | 대행사 전달 형태(화면/CSV/알림), 보존기간 |
