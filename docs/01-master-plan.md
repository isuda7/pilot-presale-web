# 01. 분양 사이트 파일럿 전체 기획

> 이 문서는 지금까지의 논의를 하나로 합친 **전체 기획의 기준 문서**다.
> 구현 범위는 `02-implementation-scope.md`, 프롬프트(원본·감시)는 `03-prompts.md`를 본다.

---

## 1. 목적과 현재 단계

- **목적**: 분양 현장 사이트를 반복해서 만들 수 있는 "파일럿"을 설계한다. 사이트를 하나 만드는 일이 아니라 **현장마다 찍어내는 구조**를 만드는 일이다.
- **관건 3가지**: ① 공통을 어떻게 가져갈까 ② 데이터를 어떻게 바꿀까 ③ 실제 분양 사이트를 어떻게 생성할까
- **현재 단계의 방식**: 파일럿을 **복제**하고, 기획 자료를 받아 **개발자가 직접 수정**해서 현장 사이트를 만든다.
- **운영 규모**: 동시 **최대 4개 현장** 기준. 도메인은 별도 처리(기획 범위 밖).
- **신청 확인**: 각 사이트의 관리자 화면 목록.

## 3. 전체 구조

```
파일럿
├─ 사용자 화면 (사이트 형태)
│   ├─ 내부용 (참조용)     = 초안 기본값   ← 모든 정보의 기본 (비공개)
│   └─ 외부용 (비즈니스용)  = 유형별 템플릿 3~4개 (공개, 가상 데이터)
└─ 매뉴얼 화면 (내부)      = 가이드 메뉴얼 (비공개)

실제 분양 현장 = 외부용 유형 템플릿 하나를 복제 → 현장 데이터로 교체
```

| | 내부용 (초안 기본값) | 외부용 (유형 템플릿) | 매뉴얼 화면 |
|---|---|---|---|
| 목적 | 기획·개발 기준 참조 | 영업·고객에게 보여주는 완성 샘플 | 만드는 방법 설명 |
| 대상 | 우리 팀 | 외부 | 우리 팀 |
| 공개 | 비공개 | 공개 | 비공개 |
| 데이터 | 임시 문구 | **가상 데이터만** | 해당 없음 |

## 4. 4개 레벨 체계

| 레벨 | 의미 | 판정 기준 (벤치마킹) | 수정 위치 | 공통 수정 전파 |
|---|---|---|---|---|
| **L1 필수 공통** | 모든 현장에 항상 있음 | 후보 전부에 있음, 또는 서비스 필수(신청, 관리자, 고지문) | 기본(템플릿 코드) | 한다 |
| **L2 선택 공통** | 있으면 쓰고 없으면 끔 | 대략 절반 이상 | 설정의 켜고 끄기 + 내용 | 한다 |
| **L3 예외 유형** | 일부 유형에만 필요한 구조 | 소수 현장 | 해당 유형 전용 모듈 | 하지 않는다 |
| **L4 현장 고유 데이터** | 값만 다름 | 현장명, 전화, 문구, 이미지, 일정, 주소 | 현장 데이터 | 하지 않는다 |

규칙
- **L3와 L4의 경계**: 구조가 다르면 L3, 값만 다르면 L4. (평면 타입 수가 3개든 8개든 L4 / 오피스텔 분리 메뉴는 L3)
- **L3 승격**: 같은 L3가 **2곳 이상에서 반복되면 L2로 승격**한다.
- 레벨의 승격·강등은 이력을 남긴다.

## 5. 덮어쓰기(오버라이드) 구조

기본은 **독립적으로 완전한 사이트**이고, 유형(사용자정의)은 **바꾸고 싶은 것만** 갖춘다.

```
기본 (그 자체로 실행됨)
   ↑ 덮어씀
유형 정의 (기본과 다른 것만)
   ↑ 덮어씀
현장 데이터
```

| 덮어쓰기 방식 | 예 | 특징 |
|---|---|---|
| 값 덮어쓰기 | 설정 값, 디자인 토큰(색상·폰트) | 가장 안전. 기본이 바뀌어도 충돌 없음 |
| 켜고 끄기 | 메뉴·섹션 사용 여부 | 안전 |
| 파일 통째로 교체 | 특정 페이지/컴포넌트를 유형 폴더의 파일로 대체 | 자유도 높음. **기본과 연결이 끊김** |

규칙
- 우선순위: 값 덮어쓰기 → 켜고 끄기 → 파일 교체(마지막 수단).
- 파일 교체를 하면 **교체한 파일 목록을 유형마다 기록**한다. (기본이 개선돼도 따라오지 않기 때문)
- 기본은 L1과 **모든 L2를 구현**해 두고, 유형은 켜고 끄기만 한다. L3는 유형이 추가한다.

### 유형 정의에 들어갈 것
이름 / 디자인 시스템(토큰, 헤더·푸터 스타일) / L2 켜기·끄기 / L3 모듈 / 페이지·메뉴 구성 / 신청 폼 항목·동의문

### 유형의 두 축
- **구조 유형**(어떤 메뉴·페이지)과 **디자인 시스템**(어떤 모양)을 독립된 두 축으로 둔다. 유형 = 구조 + 디자인 조합.
- 조합 폭발을 막기 위해 4개 현장 규모에서는 **구조 2~3종 × 디자인 2종 이내**로 상한을 둔다.

## 7. 현장 생성 (복제 절차)

```
[준비]  1. 기획 자료 수령  2. 필수 확인 항목 체크
[복제]  3. 템플릿 저장소에서 새 저장소 생성  4. clone → npm install
[수정]  5. 설정(현장명·전화·메뉴·고지)  6. 페이지 콘텐츠·이미지  7. 색상 토큰  8. 신청 폼·동의문
[연결]  9. Turso DB 새로 생성  10. Vercel Import → 환경변수 4개 (현장마다 다른 값)
[검수]  11. 로컬→배포→신청 테스트→관리자 확인→테스트 데이터 삭제  12. 기획 검수→도메인(별도)→오픈
[종료]  13. 신청 폼 닫기 → 보존기간 후 DB 삭제 → 사이트 보관/삭제
```

환경변수: `ADMIN_PASSWORD`, `TOKEN_SECRET`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`

### 현장 수정 허용 범위
- 수정 가능: 설정 파일, 페이지 콘텐츠, `public/`, 색상 변수, 신청 폼 항목
- 수정 금지: `api/`, `server/`, `layout.js`, `admin.js`, `vite.config.js`, `vercel.json` → 템플릿에서 고친 뒤 전파
- **내부용 초안과 매뉴얼 화면은 현장 복제본의 공개 배포에 포함되지 않아야 한다.**

### 공통 수정 전파
- 템플릿 저장소를 기준(upstream)으로 두고, 현장 저장소가 가져와 병합한다.
- 템플릿 버전(태그)과 현장×버전 표로 어느 현장이 어느 버전인지 관리한다.
- 공통 수정 후 4곳에서 신청 → 관리자 목록 확인을 빠르게 점검한다.

## 8. 신청 데이터와 관리자

- 현재 제공: 로그인, 신청 목록(최신순), 상태 변경(신규/연락완료/처리완료), 삭제(소프트 삭제)
- 다음 우선순위: ① 검색·기간 조회 ② CSV 다운로드 ③ 신규 신청 알림
- 개인정보: 동의 문구의 수집 항목 = 실제 폼 항목. 보존기간과 파기 절차를 종료 단계에 포함. 현장별 DB 분리로 파기는 DB 삭제로 처리.
- 관리자 인증: 현장별 비밀번호 1개(서명 토큰 12시간). 개별 계정·로그인 기록은 이번 범위 밖.
- 관리자 페이지는 검색 노출 차단(`noindex`)을 유지한다.

## 9. 가이드 매뉴얼 구성 (3개 기둥)

1. **세팅·가입·판단 노하우·프롬프트 과정**: 백엔드/프론트 초기 세팅, GitHub·Vercel·Turso 가입 절차, 헷갈리는 판단 노하우, 프롬프트로 진행한 전체 과정
2. **디자인 시스템 규칙**: 공통 범위(토큰·컴포넌트), 덮어써도 되는 것/안 되는 것, 덮어쓰기 우선순위, 파일 교체 기록 규칙
3. **10개 후보 → 4레벨 설계 활용법**: 매트릭스, 레벨 판정 기준, 설계 순서(L1→L2→L3→L4), 후보의 한계와 보강 방법

형식: 먼저 `docs/guide/` 마크다운, 이후 `/guide` 화면(비공개·`noindex`·접근 제한)으로 전환.

## 10. 현재 구현 상태 (파일럿)

- 위치: 이 저장소. 배포: https://pilot-presale-web.vercel.app (Vercel Hobby, GitHub 연동 자동 배포)
- 화면: 메인, 사업안내, 단지안내, 세대안내(빈 콘텐츠 영역), 방문예약(신청 폼), 관리자(로그인+목록)
- API: `POST /api/applications`, `POST /api/admin/login`, `GET|PATCH|DELETE /api/admin/applications[/:id]`
- DB: Turso (Vercel 연동), 테이블은 첫 요청에 자동 생성
- 설정이 `src/js/config.js`에 일부 모여 있으나 푸터·동의문 등은 아직 하드코딩
- 아직 없는 것: 레벨·유형 구조, 덮어쓰기 규칙, `.gitignore` 외 현장 복제 문서, 검색·CSV, 알림

### 이 세션에서 확인된 주의점
- 서버리스 환경에서 확장자 없는 상대 import는 함수 크래시(`ERR_MODULE_NOT_FOUND`) → `.js` 확장자 필수
- 환경변수는 저장해도 **새 배포부터** 적용된다.
- 옛 배포 URL은 고정돼 있고 Vercel 로그인 보호가 걸려 있다. 쓰는 주소는 프로젝트 도메인.
- Vercel Hobby는 약관상 상업적 사용이 제한된다. 실제 분양 운영 시 플랜 확인이 필요하다.

## 11. 남은 확인 사항

1. 기획 자료의 형태 (문서/피그마/이미지) → 반영 작업량 결정
2. 신청 폼 항목이 현장마다 다른가, 공통인가
3. 신청 데이터를 대행사에 어떻게 전달하는가 (화면 확인 / CSV / 알림)
